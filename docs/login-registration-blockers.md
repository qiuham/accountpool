## 冷却和边界

通过 Go runner 启动的任务共用跨进程锁，轮次结束后至少冷却 60 秒。本轮上游测试全部串行，没有切换出口。测试通过不意味着以后永远不会出现 Cloudflare 挑战，也没有证据证明 60 秒是 Cloudflare 的固定解除期限。

执行约束补齐：

- Python CLI 与各模块命令行入口使用同一 `.executor.lock` 和 `.last-finished`；Go 通过打开的文件描述符将锁传给 Python，再传给步骤子进程。独立 Python 命令自行获取锁并冷却 60 秒。底层库函数不隐式获取锁，外部调用应使用 `execution_guard`。
- 成功请求清零代理失败计数；未使用的代理只释放占用，保留已有失败记录；账号/配置错误不处罚代理。
- 确认的临时导航故障按 60 秒起指数退避，最多翻倍六次；挑战、拒绝访问和 429 停止当前调度轮次，代理按配置的冷却基数（默认 30 分钟）退避。该时间是本项目策略，不是 CF 解除挑战的保证。
- 重试保留出口绑定，指定出口冷却时暂停；等待出口不消耗执行次数；空代理 ID 保持 NULL，不再误读成有效的 0。
- 未知失败不自动重试。挑战是否需要人工由页面证据区分。

这些是单次端到端与本地回归验收，不代表长期压力测试。调度暂停已持久化到 SQLite：人工挑战与未知执行结果要求显式恢复；临时退避到期后才允许继续。重启 worker 不会清除暂停。

## 持续运行与恢复（2026-10-04）

- Worker 使用数据库旁的进程锁，串行执行恢复和任务领取；第二个 worker 直接退出。
- `scheduler_control` 保存暂停原因和截止时间。`accountpool worker --resume` 是明确的恢复操作，不会自动重新提交中断任务。worker 暂停退出码为 2，错误为 1。
- 受管执行进程记录 owner PID、进程组 leader PID、内核启动时间和 boot ID。只有原 owner 已退出且 leader 身份吻合才清理该进程组；身份不明或仍有活跃锁时停止，不误杀其他进程。
- 遗留 `running` 任务改为 `blocked / interrupted-unknown-outcome`，释放与该任务关联的出口占用。先检查此前产物与远端结果，再决定是否重新入队。
- 已启动进程但没有可信结果时，返回 typed unknown-outcome，不再按“启动失败”自动重试。
- 邮箱 JWT 缺失或明确 401 时，通过现有管理员 `show_password` 接口恢复，再用 `/api/settings` 校验邮箱身份，成功后才保存。服务不可用、地址不符都不会覆盖凭据或重建邮箱。
- 登录收信只解析当前服务的 `results` 格式。凭据失效、收信故障、正常等待超时分别报告，错误日志不打印邮件响应正文。
- 修复实测发现的已登录误判：就绪阶段同时接受明确聊天页面，之后仍验证 session cookie；不再先等待一个本来就不会出现的邮箱框。
- 登录按钮点击发生异常时保留“提交结果未知”，不再试点第二个按钮；成功后不读取可能已被导航销毁的元素。

职责拆分：`store/recovery.go` 管数据库暂停与任务恢复，`runner/recovery.go` 管进程身份和清理，`claude/mailbox_credentials.go` 管邮箱凭据，`backend/internal/claude/login_mail.go` 管新邮件筛选和有界轮询，Python 通过 `browser_services` 私有 IPC 等待结果。没有增加兼容入口或迁移脚本。
